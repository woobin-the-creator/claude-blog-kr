TypeScript 모드(mod)로 Claude Code 커스터마이즈하기

2026년 10월 1일 · 카테고리: Product announcements · 제품: Claude Code 원문: Customize Claude Code with mods in TypeScript (한글 번역본)

오늘 우리는 모드(mod)를 소개한다. 모드는 Claude Code의 동작 방식을 바꾸는 작은 TypeScript 함수다. 모드 하나로 프롬프트를 고쳐 쓰거나, 새 UI를 추가하거나, 내장 기능을 교체하거나, 완전히 새로운 기능을 더할 수 있다. 직접 모드를 작성할 수도 있고, Claude Code에게 대신 써 달라고 할 수도 있다. 모드는 플러그인(plugin) 안에 담겨 배포되므로, 다른 플러그인과 똑같이 설치하고 공유한다. Claude Code CLI와 데스크톱 앱 모두에서 동작한다.

모드는 Claude Code 자체와 동일한 권한으로 여러분의 컴퓨터에 접근한다. 샌드박스(sandbox)로 격리되지 않으므로, 컴퓨터에 어떤 코드든 설치할 때와 마찬가지로 신뢰할 수 있는 출처의 모드만 설치해야 한다.

모드로 무엇을 할 수 있는지 보려면 첫 모드 만들기 가이드를 읽어 보자.

모드를 만든 이유

개발자들은 우리가 기능을 출시해 주길 기다리지 않고도 Claude Code의 동작 방식을 더 세밀하게 제어하고 싶어 했다. 훅(Hooks)이 이런 제어권의 일부를 제공했지만, 훅은 이벤트를 고쳐 쓰거나, 새 UI를 그리거나, 기능을 교체할 수는 없다. 모드는 할 수 있다.

우리는 Claude Code가 여러분의 것처럼 느껴지길, 그래서 자신의 일하는 방식에 맞게 빚어 갈 수 있길 바란다. 출시에 앞서 개발자들의 피드백을 받기 위해 모드의 설계를 GitHub에 공개했다. 의견을 보태 준 모든 분께 감사드린다.

모드의 동작 방식

Claude Code는 무언가를 할 때마다 이벤트(event)를 내보낸다. 도구를 호출하거나, 권한을 요청하거나, 화면의 일부를 그리는 일이 그 예다. 모드는 이 이벤트 중 하나에 끼어드는 함수다. 모드는 이벤트 전에, 후에, 또는 이벤트를 대신해 실행될 수 있다. 이벤트를 감싸서(wrap) 전후에 모두 코드를 실행할 수도 있다. 함수 하나로 모드는 다음을 할 수 있다.

  • 프롬프트가 모델에 도달하기 전에 고쳐 쓴다.
  • 도구 호출을 차단하거나, 고쳐 쓰거나, 재시도한다.
  • 권한 요청을 승인하거나 거부한다.
  • Claude가 읽기 전에 도구 출력에서 비밀 값(secret)을 가린다.

모드는 여러분이 보는 화면도 바꿀 수 있다. 도구 결과나 Claude의 질문처럼 Claude Code가 그리는 인터페이스의 일부를 편집하거나 교체할 수 있다. 버튼과 입력란을 추가할 수 있고, 여러분이 그것을 누르면 다른 모드가 반응할 수 있다. 현재 모드는 터미널, 데스크톱 앱, 또는 둘 모두를 대상으로 할 수 있다.

여러 모드가 같은 이벤트에 끼어들면, 로드된 순서대로 실행된다. 가장 먼저 로드된 모드가 이벤트를 가장 먼저 보고, 결과는 가장 나중에 본다. 덕분에 서로 다른 제작자의 모드를 겹쳐 쌓을 수 있다.

Claude Code를 써서 Claude Code를 모딩할 수도 있다. Claude에게 모드를 만들어 달라고 하면 TypeScript를 작성하고, 설치하고, 현재 세션에 핫 리로드(hot reload)까지 해 준다.

내장 기능을 내 것으로 바꾸기

Claude Code의 일부 내장 기능은 이제 모드 형태로 제공된다. 예를 들어 내장 /diff 기능은 이제 모드이므로, (/plugin에서) 끄거나 직접 만든 버전으로 교체할 수 있다. 앞으로 더 많은 내장 기능을 모드로 옮겨 갈 계획이다. 그러면 Claude Code를 작은 코어(core)로 줄이고, 원하는 것만 다시 더할 수 있다.

팀과 기업을 위한 모드

모드는 플러그인 안에 담겨 배포되므로, 기존의 플러그인 제어가 그대로 적용된다. 관리자는 플러그인 마켓플레이스(marketplace)를 허용하거나 차단할 수 있다. Team과 Enterprise 플랜에서는 소유자(owner)가 관리자 콘솔(admin console)에서 이를 설정한다. Claude API와 서드파티 API 플랜에서는 관리자가 관리형 설정(managed settings)을 사용자의 컴퓨터에 배포한다.

Team과 Enterprise 플랜, 그리고 관리형 설정이 적용된 모든 컴퓨터에서는 sec-default("security default")라는 내장 모드가 가장 먼저 로드된다. 이 모드는 사용자가 설치한 모드가 권한 거부 규칙을 덮어쓰는 것 같은 위험한 일을 하지 못하게 막는다. 무엇을 제한하는지는 소스 코드에서 확인할 수 있다. 관리자는 대신 자신의 모드를 가장 먼저 로드할 수도 있다. 그렇게 할 경우, 목록에 sec-default를 포함시켜 그 제한을 유지하자.

팀은 모드로 자체 제어 장치와 기능을 만들 수도 있다. 예를 들면 다음과 같다.

  • CI/CD 상태: 모드가 대화 옆 창(pane)에 파이프라인 상태를 보여 주고, 빌드가 통과하거나 실패할 때마다 갱신할 수 있다.
  • 프로덕션 안전장치: 모드가 프로덕션 설정을 건드리는 모든 명령에 앞서 확인을 요구할 수 있다.
  • 감사 로깅(audit logging): 가장 먼저 로드되는 모드가 다른 모든 모드의 모든 호출을 기록할 수 있다.

시작하기

모드는 오늘부터 Claude Code CLI와 데스크톱 앱에서 사용할 수 있다. 모드가 포함된 플러그인은 Claude 디렉터리에서, 또는 CLI에서 /plugin을 실행해 설치한다. 모드를 공유하려면 플러그인으로 패키징한 뒤 디렉터리에 제출하면 된다.
